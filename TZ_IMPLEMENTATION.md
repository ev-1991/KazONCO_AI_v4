# KazONCO AI — соответствие техническому заданию

## Реализовано в прототипе

- Авторизация пациента по номеру телефона и одноразовому SMS-коду (демо-код `123456`).
- Явное согласие на обработку персональных и медицинских данных, хранение версии и времени согласия, отзыв согласия.
- Профиль: регион РК, пол, дата рождения/возраст, диагноз с подсказками МКБ-10 для рака лёгкого, стадия I–IV.
- Чат: история, источник ответа, уровень риска, красные флаги, передача врачу при неопределённости/опасности.
- Post-MVP: ежедневный мониторинг самочувствия и симптомов, история чек-листов, автоматическая регистрация тревоги.
- Единая история пациента: чаты, ежедневный мониторинг, тревожные сигналы.
- Карточка текущей терапии как точка интеграции `GET /patients/me/treatments`.
- Мобильная нижняя навигация: Чат / Мониторинг / История / Пациент.
- RU/KZ/EN; обязательные RU/KZ сохранены.
- Существующие панели врача, администратора, аналитики и аудита сохранены.

## Модель данных прототипа

Для пациента используются: `profile`, `consents`, `treatments`, `conversations`, `dailyCheckins`, `adverseEvents`, `alerts`, `documents`. В промышленной версии эти структуры должны храниться в серверной БД.

## Точки API из ТЗ

- `POST /auth/login` — телефон + OTP.
- `GET /patients/me` — профиль.
- `GET /patients/me/treatments` — курсы и препараты.
- `POST /adverse-events` — симптомы/нежелательное явление.
- `GET /adverse-events/{id}` — статус обработки.
- `POST /attachments` — вложения.
- `POST /ai/analyze` — обезличенный запрос ИИ.
- `GET /alerts` — тревожные сигналы.
- `GET/POST /chats/{patient_id}/messages` — история и отправка сообщений.

## Важно для production

Текущая сборка — интерактивный frontend-прототип. OTP, API, TLS, шифрование at-rest, антивирусная проверка файлов, OAuth2/mTLS, серверный аудит, резервное копирование, хранение ПД и SLA 99.5% должны быть реализованы на backend/инфраструктуре. Ключи внешних AI API нельзя хранить в мобильном или frontend-коде.
